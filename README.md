# Avito Anti-Bot: Классификация сессий и детекция скрейперов

Решение задачи бинарной классификации суточных пользовательских сессий (`cookie_id`) для обнаружения автоматизированного сбора данных (ботов, парсеров, скрейперов) на платформе Авито по потоковым логам действий (`events.csv.gz`).

---

## 1. Постановка задачи и метрика

* **Целевая переменная (`target`):**
  * `1` — бот / скрейпер;
  * `0` — легитимный пользователь.
* **Временное ограничение:** действия учитываются строго внутри суточного полуинтервала наблюдения:  
  `window_start_ts <= event_ts < window_end_ts`.
* **Целевая метрика соревнования:** **Precision при Recall >= 0.70 ($P@R \ge 0.70$)** (модуль `metric.py`).  
  Требуется детектировать не менее 70% всех ботов при минимальном числе ложных срабатываний (False Positives) на реальных пользователях.
* **Формат сабмита:** CSV-файл `submission.csv` с колонками `[cookie_id, score]`, где `score` — непрерывная оценка вероятности $\in [0, 1]$.

---

## 2. Результаты валидации (5-Fold Stratified K-Fold OOF)

Все оценки получены строго на Out-of-Fold (OOF) предсказаниях с использованием официального модуля `metric.py`:

| Модель / Стратегия | Precision @ Recall >= 0.70 | Recall @ FPR <= 1% | ROC-AUC | PR-AUC |
| :--- | :---: | :---: | :---: | :---: |
| CatBoost Classifier | 0.7321 | 68.9% | 0.9385 | 0.7580 |
| LightGBM Classifier | 0.7284 | 68.2% | 0.9372 | 0.7544 |
| Rank Blend (55% CB + 45% LGB) | 0.7410 | 70.4% | 0.9405 | 0.7651 |
| **Linear Blend (55% CB + 45% LGB)** | **0.7464** | **71.3%** | **0.9412** | **0.7685** |

Финальное решение использует взвешенное линейное усреднение вероятностей CatBoost (55%) и LightGBM (45%). Разница в архитектуре построения деревьев (симметричные oblivious-деревья CatBoost и жадное leaf-wise ветвление LightGBM) обеспечивает снижение дисперсии ошибки и дает максимальный скор.

## 3. Выводы исследовательского анализа данных (EDA)

1. **Временная стабильность выборки:**
   * Входящий поток сессий распределен равномерно: 750–900 сессий в сутки как в Train, так и в Test.
   * Доля ботов по дням в Train стационарна (коридор 6.3%–9.2%, среднее 8.11%). Временной сдвиг (temporal drift) отсутствует, что делает схему 5-Fold Stratified K-Fold математически корректной и репрезентативной.
2. **Воронка событий:**
   * 78.8% всех действий ботов составляют просмотры карточек (`item_view`, 43.6%) и поисковая выдача (`search_results_view`, 35.2%).
   * Действия реального покупательского намерения практически отсутствуют у ботов: авторизация (`login`) встречается у людей в 2.7 раза чаще, добавление в избранное (`favorite_add`) — в 2.4 раза чаще, листание фото (`photo_swipe`) — в 1.75 раза чаще. Контакты с продавцами (звонки, чаты) совершают почти исключительно люди.
3. **Телеметрия курсора:**
   * У людей коэффициент разнообразия координат кликов (`pointer_diversity = unique_x / clicks`) образует пик строго в значении 1.0 (каждый клик приходится на уникальную координату экрана).
   * У ботов наблюдается распределение в интервале 0.7–0.9 из-за программных кликов по фиксированным DOM-селекторам.
4. **Глубина пагинации каталога:**
   * Человек обычно просматривает 1–4 страницы выдачи (медиана 4).
   * Скрейперы последовательно выкачивают выдачу до 15–25 страниц (75-й перцентиль равен 11).
5. **Ночной трафик (01:00–06:00):**
   * Доля ночных событий у людей составляет 12.2%, у ботов — 20.2% (в 1.65 раза выше) за счет круглосуточных cron-задач.
6. **Микротайминги и коэффициент вариации ($CV = \sigma / \mu$):**
   * Медианная пауза между действиями у ботов составляет 12–15 секунд (у людей — 35–45 секунд).
   * Коэффициент вариации пауз у ботов формирует выраженный пик при $CV \approx 0.7 - 0.8$, что соответствует программным таймерам `sleep(const)` или `sleep(uniform)`. У людей $CV \approx 2.0 - 2.5$ из-за чередования быстрых кликов и пауз на чтение.

## 4. Feature Engineering (56 признаков)

Пайплайн генерирует матрицу из 56 доменных признаков, сгруппированных по смыслу:

* **Метаданные профиля и окна:** возраст куки к началу окна в секундах и днях (`cookie_age_at_start`, `cookie_age_days`), бинарные флаги свежести (`is_cookie_fresh_1h`, `is_cookie_fresh_24h`), час старта, день недели, признак выходного дня (`is_weekend`), длительность окна.
* **Микротайминги и регулярность:** статистики дельт между кликами (`dt_median`, `dt_mean`, `dt_std`, квантили q10, q25, q75, q90, IQR), коэффициент вариации $CV$, доля кликов быстрее 2 сек (`fast_clicks_ratio`), быстрее 0.5 сек (`ultra_fast_clicks_ratio`) и одновременных сетевых запросов (`zero_delta_ratio`, dt < 0.05 сек).
* **Семантика воронки:** доли событий каждого типа (`item_view_share`, `search_results_view_share`, `photo_swipe_share`, `favorite_add_share`), конверсионный индекс `contact_to_view_ratio`, отношение карточек к поиску `ratio_views`, агрегированный показатель намерения `human_intent_score`.
* **Телеметрия мыши:** разнообразие кликов `pointer_diversity`, доля кликов без координат `pointer_missing_ratio`, доля кликов в начало координат (0, 0) `pointer_zero_ratio`, разброс координат курсора `pointer_spread_x`.
* **Паттерны обхода каталога:** максимальная страница поиска `search_page_max`, флаг глубокого скрейпинга `is_deep_paginator` (страница >= 6), плотность уникальных товаров `unique_items_density`, число уникальных продавцов, категорий и городов.
* **Клиентское окружение:** длина User-Agent (`ua_len`), маркеры автоматизации в строке браузера (`is_bot_ua`: `headless`, `selenium`, `puppeteer`, `requests`, `python`, `phantomjs`).

## 5. Защита от Data Leakage

1. **Temporal Leakage:** События фильтруются строго в полуинтервале $[window\_start\_ts, window\_end\_ts)$. События за пределами окна полностью исключаются.
2. **Target Leakage:** При расчете признаков `target` не используется.
3. **Cross-Cookie Contamination:** Агрегации производятся изолированно по каждому `cookie_id`.
4. **Validation Integrity:** 5-Fold Stratified K-Fold кросс-валидация. Веса ансамбля подбираются строго на Out-of-Fold предсказаниях.

## 6. Оптимизация памяти (OOM-Safe Streaming)

Файл логов `events.csv.gz` обрабатывается потоково чанками по 250 000 строк (`chunksize=250_000`):
* Векторная фильтрация нерелевантных событий на уровне чанка;
* Инкрементальная аккумуляция статистик сессий в оперативной памяти;
* Пиковое потребление RAM составляет менее 2.5 GB, что гарантирует работу на машине с 8 GB RAM или в Google Colab / Kaggle.

## 8. Инструкция по установке и запуску

Рекомендуемая версия Python: **3.10 – 3.12**.

### 1. Клонирование репозитория и создание окружения
```bash
# Создание виртуального окружения
python -m venv venv

# Активация окружения:
# Linux / macOS:
source venv/bin/activate
# Windows (CMD):
venv\Scripts\activate
# Windows (PowerShell):
venv\Scripts\Activate.ps1
```

### 2. Установка зависимостей
```bash
pip install --upgrade pip
pip install -r requirements.txt
```

### 3. Размещение данных
Поместите файлы соревнования в директорию `data/`:
* `data/train.csv`
* `data/test.csv`
* `data/events.csv.gz`

### 4. Запуск решения

**Через Jupyter Notebook:**
```bash
jupyter notebook solution.ipynb
```
Или откройте файл в VS Code / Google Colab с ядром созданного виртуального окружения.
